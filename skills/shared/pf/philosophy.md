# pf 系统设计哲学

> 本文件描述 pf 系统的背景与设计原则，供 pf-route 引用，不重复叙述。

## 核心问题

开发时思维会自然跳跃：做着功能 A，脑子里冒出 B/C/D 的想法。这些想法记不住，记到 docs/ 又污染 source of truth——agent 分不清"已实现"和"未来计划"。试图保持想法在脑中则影响当前工作的专注度。

## 系统目标

**外置大脑。** 把想法从人脑卸到结构化存储中。用户清空大脑后能专注当前工作，想法不会丢失也不会遗忘。

## 关键设计

### DAG 而非列表

想法之间有自然的依赖关系（B 需要 A 完成后才能做）。线性列表丢失了这个结构，手动优先级会过时。

图的拓扑结构自动推导两个核心指标：

| 指标 | 含义 | 图算法 |
|------|------|--------|
| **urgency**（紧急性） | 现在能不能开始做 | 拓扑位置靠前的节点 = 依赖已满足 = 最 urgent |
| **importance**（重要性） | 有多少东西依赖它 | 反向可达集大的节点 = 被很多人依赖 = 最 important |

这两个指标只对**未完成**节点计算。一个节点完成后，依赖它的节点自动变得 more urgent，urgency/importance 动态更新，不需人工调整。

两者组合形成**四象限决策框架**（Eisenhower Matrix 在 DAG 上的对应），是 Agent 帮助用户判断节点取舍的依据：

- **又紧急又重要**（入度小 + 出度大）：依赖少随时可做，且被很多人依赖。基石功能，MUST DO NOW。最高优先级。
- **重要但不紧急**（入度大 + 出度大）：影响很大但前置依赖未完成。当前做不了，优先解它的前置节点。
- **紧急但不重要**（入度小 + 出度小）：依赖少随时能做，但没被依赖。做了也不影响其他人，考虑是否值得投入时间。
- **不紧急也不重要**（入度大 + 出度小）：既不 urgent 也没人依赖。冰盒，优先级最低。

### 完成的节点不删

做完的节点标 `completed`，节点目录留在原地——文件系统里不会残留无人维护的孤立 MD 文件。想法本身作废、用户要它出图时，才用 `pf dag rm` 真删。

实际操作中 `pf dag list` 默认全量显示但按 urgency×importance 排序，completed 节点排在末尾（不显示 score）。如果其他节点的 `deps` 中出现你没见过的 UUID，那很可能指向一个 completed 节点——用 `pf dag list --status completed` 确认，不要直接判定为 dangling ref。

### Ground truth 纯净

未来计划全部迁入 pf 系统后，项目 docs/ 只包含已实现的内容。读 docs/ 的 agent 可以信任读到的是现状，不再混淆"这是计划还是已实现"。

不是每件事都进图：让文档追上现状、跑一次探针回答一个可行性问题、非行为性的小改，就地做完即可（判据见 pf-route 的「现在就做」）。图装的是"要做什么"，这些活写的是"现在是什么"。

## 与已有 skill 的关系

**pf-conduct** 管线（pf-conduct 一个节点做完：准备、执行、独立复审、修复、收尾）回答的是"怎么实现"。

pf 系统回答的是"我们要做什么"——作为 pf-conduct 管线的上游输入。idea 从 pf-route 进入 DAG，由 pf-conduct 细化并执行。
