# 压缩判据

> 供 scan subagent 使用，与 `garbage-patterns.md` 一起读。判据只看一件事：**这一条给快档的墙钟加了多少**。一条测试验得对不对，归 `garbage-patterns.md` 管。

## 判什么

一条测试被算作拖慢快档，只要它满足下面任一条：

1. **它在快档里，而且贵**：起真子进程、读真实文件系统之外的东西、等真墙钟、加载模型、开端口、跑网络。
2. **它在快档里，而且属于项目自己的慢档判据**（项目文档里通常写了归位判据：真服务子进程 / 真墙钟等待 / 注入慢模型 / 单条实测超阈值）。
3. **项目没有分档**，而它在全量里明显拖长整个套件的墙钟。

判据以**项目文档为准**。项目自己定了线（比如"快档每圈 ≤10 秒"）就用它的线；没定就报事实（这条多久、占了套件多少）。

## 能拆的怎么拆

一条测试里可能混着两种断言：

- **纯逻辑 / 纯结构的断言**——毫秒级，不依赖子进程、时钟、模型。这些**提出来进快档**。
- **依赖真实环境的部分**——留在慢档。

拆出来的快档测试必须**自己成立**：不依赖慢档留下的状态，不靠共享 fixture 的副作用，拆完能在快档里单跑。

> 拆是比整条挪走更好的动作：压缩和覆盖同时满足。所以扫描时先看能不能拆，拆不动才整条挪。

## 两种移档方式

选哪种看项目：

- **标记**（有标记机制时，如 `slow`）：给慢的那条或那个文件加标记，快档命令自己会滤掉它。
- **入口**（项目把快慢做成两个命令/两个目录时，如 `tests/` 与 `bench`）：把条目挪到慢的那个入口，并同步构建/收集清单。

**项目没有快慢分档时，自己建一个。** 压不下去的那几条（起真子进程、等真墙钟、加载模型、开端口）单独拆成一个慢档：给它一个入口或一个标记，把这几条挪过去，构建与收集清单同步改掉。建完两档各跑一次，实测读数报出来。

## 别做的事

- **不许用删除换时间。** 慢但验的是真业务的测试，正确动作是挪或拆；删它 = 删覆盖。
- **不许把慢档的断言搬进快档来"凑数"**——只有毫秒级的纯逻辑断言才配进快档。
- **不许为了让数字好看而跳过验证**：改完的快档必须真跑一遍，报实际墙钟。

## 返回格式

与 `garbage-patterns.md` 的返回格式合并成一份，每个 finding 都带这两格：

```json
{
  "file": "tests/test_example.mjs",
  "findings": [
    {
      "test_name": "壳的本命：只监听 127.0.0.1",
      "quality": { "type": "hardcoded-count", "line_start": 15, "line_end": 22, "judgment": "entire" },
      "compression": {
        "slows_fast_lane": true,
        "reason": "起真服务子进程 + 等真墙钟",
        "splittable": [
          { "what": "端口解析函数的纯逻辑断言", "lines": "31-38" }
        ],
        "action": "move"
      }
    }
  ]
}
```

- `quality.judgment`：`entire`（整段全是垃圾断言）/ `partial`（混合，只删垃圾行）/ `none`（验的是真东西）
- `compression.action`：`move`（移出快档）/ `split`（能拆，拆的快断言见 `splittable`）/ `none`
- **删不删由指挥者按动作表判**：只有 `quality.judgment` 为 `entire` 或 `partial` **且**覆盖门槛过得去，才谈删除。你只报事实，不报"建议删"。
