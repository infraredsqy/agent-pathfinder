# 子 agent：一次派几个

> 值不在这里。派活之前跑 `pf config get max_agents` 读它：全局那份在 `~/.pf/config.json`，项目那份在 `<项目>/.pf/config.json`，出厂默认写在工具里。`pf config list` 会连这个数来自哪一层一起印出来。这份文件只写怎么用它。

**它是管线自己估的一个数**：不查宿主，也不认哪一个基座软件。管线没有常驻窗口，所以也不在会话之间对表——开一个子 agent 写一次文件、关一个再写一次，这个形态不走。各会话照这个数自己估。

## 怎么用

派活之前数一次进行中的：`进行中的 + 这次要派的 ≤ 上限`。越不过就按这个顺序退让：

1. **合并**：一个子 agent 装几件事。面照旧拆成几份（每份一份发现，各自三层定位），派的时候把几份写进同一个 prompt。
2. **分批**：并完还是越不过，就等这一批的通知回来再派下一批。

合并时每一份仍要单独成篇：报告里一份一篇，别糊成一段，那样合并入库时没法去重。

## 为什么留余量

撞上上限时那一批会一起崩，整批全没。同时开着的另一个会话也占着名额，所以宁可估保守一点，也别贴着顶用。
