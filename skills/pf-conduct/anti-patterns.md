# pf-conduct 错题本

开工前对照查一遍。`subagent-anti-patterns/` 下的两份按绝对路径传给对应 subagent。

这里只留**没有任何工具会当场拦你、但你自己会不知不觉犯**的那几条；规则本身都在 SKILL.md 里。

## NC5：指挥者把复审的 critical 判成误报

**症状**：不认同复审结论，自己判一句「这个不算问题」放开。

**纠正**：把争议写成新的验证 prompt，重跑一次复审。判「误报」的权力在用户手里。

## NC11：睡一会儿再看一眼 subagent 干完没有

**症状**：派完 subagent，用 `Start-Sleep` 配 `Test-Path` 隔一阵查一次它的产物，或者反复 `list_agents`。时长是拍的（90 秒、240 秒），每轮白烧一段墙钟，轮询还写进日志当"进度"。

**实例**：一个节点的会话里攒了 22 段这样的等待，每段都配一句 `# wait-guard: 必要等待 - 等某个 subagent 写出 report.md`——豁免声明是留给等时间本身的事的，等 subagent 不等于等时间。

**纠正**：派完就结束这一轮，它完成时通知会把你唤醒、报告已入上下文。`# wait-guard:` 留给退避重试、限流窗口这类等时间本身的事。

## NC12：报告越写越肥

**症状**：两个方向。正文的数字变了就在旁边补一句「**历史读数**：……见 §17.7」，旧读数原地留着——一个节点里正稿 429 行，配 2017 行的 `report.md`。反过来，派 Execute 时只点名 `report.md` 一个落盘文件，长引用、原始输出、样本数据全写成「贴进 report」——六份零件报告 2122 行，其中正稿 429 行。

**为什么危险**：报告每个角色都要读一遍。旧读数留在正文里，后面几棒的 agent 会拿它当现行值——一个节点收尾时列的 9 条「已知未解决」里，4 条出在报告与正文脱同步上。

**纠正**：过期读数改掉或删掉，正文只留现值。派 Execute 的 prompt 里给每样产物一条落盘路径：长引用、原始输出、样本数据各走各的文件；只有判断、没有独立物料的工序，写明「只进报告，一行一条」。

## NC13：拿数字持平当收敛

**症状**：复审连着报 `critical=0, minor=10`，指挥者看数字没涨就接着派下一轮；或者同一处改了三四遍、每轮换个位置出新 critical，还照着复审的话往下改。

**为什么危险**：复审的活儿是「把所有问题找出来」，这个活儿永远有剩；数字持平既可能是收尾，也可能是缺口在换位置。两个干活的人都看不见历史——复审 prompt 每轮逐字相同、执行者只看当轮 issue 列表——能比较前后轮同一性标记的只有指挥者。少这一次比较，一个节点能磨到九轮；同一处能跨两个节点、七轮复审。

**纠正**：读复审首行的同一性标记：连着两轮落在同一批位置就是卡死。卡死时先回头核目标文档——冲突出在自己推出来的那条约束（预算、配额、上限）就改掉它，别派修复也别问用户；目标文档里真判不出来才报用户。

## NC14：分不清哪条约束是谁定的

**症状**：某个节点的会话算出一笔预算或一个上限，写进文档时和用户的要求一样措辞；后面几个节点照抄引用，它就成了谁都动不了的硬约束。再往后，agent 读上游文档时分不出哪条是机主要的、哪条是前面某个节点的会话顺手拍的，只能全部当真，继续往上加。两层、三层，最后自己都算不清在替谁守规矩。

**实例**：`Network` 的目标文档（`social-model-goals.md`）里没有"章／段／位子"任何一个字，设计约束五条全在体验层（队伍得有人、不能天天内讧、好感度看得见）；"一章最多三段"是 `content-budget.md` 某个节点的会话自己算的，被 `event-spec`／`runtime`／`mechanics-diff`／`scenes` 逐层引用，最后和另一条自己拍的"指定图要占满它开门那一章"顶死，在中间磨了五轮、跨了两个节点。

**为什么危险**：约束冲突时，指挥者分不清该让步哪一条，于是停下来问机主——让机主来收拾 agent 自己堆出来的约束。机主那边看，这是很 minor 的事，而且根本不在他的意图里。

**纠正**：备料给每条硬约束标出处——用户原话／目标文档／前面某个节点推出来的。第三类下面标一句「推出来的」，别写成和用户要求一样的措辞。卡死时先核目标文档：冲突出在自己推出来的那条就删掉它，记进自主决策清单；翻遍目标文档仍判不出来的才报用户。

## NC16：手工改 `.pf/` 里的文件，或自己裁合并冲突

**症状**：为了让两边的图对上，自己 read 并编辑 `.pf/ideas.json` / `.pf/state.json`；或者 pull 停在冲突上，按行把两份 JSON 拼起来。

**为什么危险**：那几份文件归工具管——整份重写、键序固定、status 有偏序、cycle 的 `path` 是追加记录、`holding` 同时是跨机的认领标记。手改会把这些不变量打散；行级拼接多半造出两份都读不了的 JSON，下一棒连图都打不开。

**纠正**：合并走 `pf` 驱动（每台机器 clone 后注册一次，见 `docs/conduct-state.md`「记录的落点与合并」）。驱动举旗时，把它点名的那条（哪条目的哪个字段、两侧各是什么）交给用户，别自己裁。
