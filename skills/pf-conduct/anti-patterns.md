# pf-conduct 错题本

开工前对照查一遍。这里只留**没有任何工具会当场拦你、但你自己会不知不觉犯**的那几条；判据正文在 SKILL.md 里。

## `conduct-treats-critical-as-false-positive` · 指挥者自行裁定复审结论为误报

**症状**：不认同复审结论，自己判一句「这个不算问题」放开。

**纠正信号**：报告里写着「这条是误报」，而重跑的那一次复审从来没发生过。

## `conduct-polls-for-subagent-completion` · 以轮询等待 subagent 完成

**症状**：派完 subagent，用 `Start-Sleep` 配 `Test-Path` 隔一阵查一次它的产物，或者反复 `list_agents`。时长是拍的（90 秒、240 秒），每轮白烧一段墙钟，轮询还写进日志当"进度"。

**实例**：一个节点的会话里攒了 22 段这样的等待，每段都配一句 `# wait-guard: 必要等待 - 等某个 subagent 写出 report.md`。

**纠正信号**：日志里成对出现 `Start-Sleep` 与 `Test-Path`。`# wait-guard:` 留给退避重试、限流窗口这类等时间本身的事。

## `conduct-flat-count-read-as-convergence` · 以复审计数持平认定收敛

**症状**：复审连着报 `critical=0, minor=10`，指挥者看数字没涨就接着派下一轮；或者同一处改了三四遍、每轮换个位置出新 critical，还照着复审的话往下改。

**为什么危险**：复审的活儿是「把所有问题找出来」，这个活儿永远有剩；数字持平既可能是收尾，也可能是缺口在换位置。两个干活的人都看不见历史——复审 prompt 每轮逐字相同、执行者只看当轮 issue 列表——能比较前后轮同一性标记的只有指挥者。少这一次比较，一个节点能磨到九轮；同一处能跨两个节点、七轮复审。

**纠正信号**：复审首行的同一性标记连着两轮落在同一批位置。

## `conduct-constraints-without-provenance` · 约束未标出处，自推约束被逐层当作硬约束

**症状**：某个节点的会话算出一笔预算或一个上限，写进文档时和用户的要求一样措辞；后面几个节点照抄引用，它就成了谁都动不了的硬约束。再往后，agent 读上游文档时分不出哪条是机主要的、哪条是前面某个节点的会话顺手拍的，只能全部当真，继续往上加。两层、三层，最后自己都算不清在替谁守规矩。

**实例**：某个项目的目标文档（`goals.md`）里没有"章／段／位子"任何一个字，设计约束五条全在体验层（读者不会被卡着等、两块面板不打架、目录随时看得见）；"一章最多三段"是 `layout-budget.md` 某个节点的会话自己算的，被 `section-spec`／`render`／`diff-check`／`outline` 逐层引用，最后和另一条自己定的"指定图要占满它开门那一章"顶死，在中间磨了五轮、跨了两个节点。

**为什么危险**：约束冲突时，指挥者分不清该让步哪一条，于是停下来问机主——让机主来收拾 agent 自己堆出来的约束。机主那边看，这是很 minor 的事，而且根本不在他的意图里。

**纠正信号**：一条「必须／不许／一律／上限是」翻遍用户原话与目标文档都找不到出处。

## `conduct-hand-edits-ledger-or-resolves-conflicts` · 手工编辑 `.pf/` 记录文件或自行裁断合并冲突

**症状**：为了让两边的图对上，自己 read 并编辑 `.pf/` 下的记录文件；或者 pull 停在冲突上，按行把两份 JSON 拼起来。

**为什么危险**：那几份文件归工具管——整份重写、键序固定、状态有偏序、路径是追加记录、持有关系同时是跨机的认领标记。手改会把这些不变量打散；行级拼接多半造出两份都读不了的 JSON，下一棒连图都打不开。

**纠正信号**：工作区里出现手工编辑过的记录文件，或一段按行拼起来的 JSON。
