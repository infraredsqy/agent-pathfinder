# 维护度量：测试套件的实测耗时

> 这是 `plugins/test-audit/` 自己的设计出处：这条度量量什么、数从哪儿来、线与标签是什么意思、这笔
> 债怎么算还清、读不到数时怎么办。声明认领的名字（旋钮、去重标签、方法名、读数来源）不在这里抄第二
> 份 —— 它们在 `plugin.json` 里，`pf doctor` 印得出；这里只说它们各自是什么意思。

## 这条度量量的是什么

量的是这个项目的测试套件整套跑一遍的**实测墙钟秒数** —— 掐着表跑出来的时间，用例条数和估算都替代不了
它。套件跑一遍是项目每次验证都要付的固定开销；它长到「跑一遍不如不跑」，就成了一笔债：它推着人少跑、
绕过它跑，而每绕过一轮，都是拿别的债换这一笔。

所以这个数只有一种读法：跑一遍，量。估出来的数不算读数 —— 它跟一条固定的线没法比，也比不出这一趟是变快
了还是变慢了。

## 数从哪儿来

**由跑过那次验证的会话报。** 只有真跑过整套测试的那一轮知道它花了多少秒；工具不替它跑，也不替它猜。声明
把这一项写进交接单要问的读数里，会话填、核心原样存下，判定那一步再拿它跟线比。

**这个数从不由插件自己算。** 这条债没有可以问的工具：起一次子进程量一遍，量到的是「这一趟的量法」，
跟「这个项目验一次要多久」隔着一次真跑过的全量。数从会话来，这是它的形状。

## 线与标签

**线（the line）是一个数值旋钮，名字在声明里。** 它说下次收尾必须读到多低的秒数 —— 「还能接受的最慢」那
一个数。声明不给它出厂值：没人写，这个数就不问也不判；线写在链上的哪一层，就按哪一层判。

**标签（the dedupe tag）挂在插进去的节点上**，回答「这个度量是不是已经有一个节点在局中」；挂着一个，下一
次越线就先等着。

## 判定与开关

**比较是 `>=`。** 线是还能接受的最后一个数：读到它，债就到顶了，节点就该插。

**只判关于代码的线。** 带代码那一类 tag 的线才判这一条；别的线读得到同一个数，但既不插也不等。

**开关关掉就整条让路**：越线也不插。这个插件没有要起的子进程（数不是它算的），所以关掉它只是不判。

## 生成的 spec 与完成判定

生成的 spec 里，这条债的完成判定写的是：**下一次收尾的交接单上，量到的秒数必须低于线**；看这个数的办法是
跑一遍项目文档认定的整套验证命令并**实测**（不许估），把量到的秒数报回来。

## 这笔债怎么算还清

**还清就是重新量出来的那个数。** 体检节点把该删的删掉、该挪出快档的挪出去、该拆的拆开；下一次全量跑一
遍，量到的秒数就是新的读数 —— 它低于线的那一刻，债就清了。这里没有要另外核销的记录：这个数就是套件本身
的读数，跑一遍就刷新，不必谁来另记一笔。

节点照常收尾、线接着走下一个，不停下来等人回话。判据不成立（量下来还压在线上下不来）时，交接单写「没交
付」并把这个秒数写进去：债留在明处。

## 读不到这个数时

**没量到的那个键整个删掉：缺一个数读作「这一趟不知道」，绝不补 0。** 0 会让一笔真实的债看起来已经还清。
这一趟没有数就不插节点 —— 不知道不等于还清，也不等于到顶。

不知道不等于慢下来：套件还是那么慢，下一次收尾再量。
