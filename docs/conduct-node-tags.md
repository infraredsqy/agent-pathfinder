# conduct 的节点 tag 与 cycle 分流

> 这份是**节点 tag 与 cycle 分流**的设计出处：词表、过滤的判据、为什么过滤只落在挑人那一步。
> 状态与推进的其余部分见 [`./conduct-state.md`](./conduct-state.md)；派发与鉴权见
> [`./conduct-dsh-dispatch.md`](./conduct-dsh-dispatch.md)；两条 active cycle 并排时指令作用域的可见性，
> 归状态与推进契约里讲派发的那一节。
>
> 规则一句话：**节点可以没有 tag；cycle 的 `tags` 是这条线的选材范围（它一生里每一次挑选都用这
> 一份）；过滤只作用在「挑下一个节点」这一步。**

## 0. 为什么要有它

图一旦同时装着文案、代码、图像三类活，「这条线在做什么」就散在每一轮的挑选结果里 —— 人想开
一条只做文案的线、或者只想让一条线碰代码，没有办法说出来。

tag 就是这句话：给节点打 tag（这件事属于哪一类活），给 cycle 一个过滤集（这条线在哪些节点里
挑人）。开一条带 `--tags coding` 的线，从此只挑代码的活 —— 第一个节点到最后一个节点，用的是
同一份过滤集。

## 1. 词表

三个词，固定：`writing`（文案）、`coding`（代码）、`art`（图像）。

词表是**给人看的一份约定**，engine 不拿它当硬性规定：词表外的 tag 警告一行，照收 —— 真冒出第四类
工作时写进去就能用，警告只是让人知道自己站在词表外。过滤一律按字面比。

## 2. 为什么落在那两处

- **节点上的 tag 落在图里**，因为它是图的一部分：谁属于哪一类活，和它依赖谁、什么状态一样，是图自己说的话。
- **cycle 上的过滤集落在这条线自己的记录里**，因为它是**这条线**的属性：一条线只挑一类活，这件事跟着线走，不跟着某一次挑选走。开机那条命令把过滤集**同时**交给挑选与记录 —— 挑选发生在 cycle 建起来之前，只写记录就太晚了，第一个节点就会挑到别的线的活；此后每一次挑选都从那里读回来复用，「第二次挑到了别的线的东西」这种漂移没有地方发生。
- **两边不对称。** 节点上的 tag 可选 —— 没有它时图里根本不出现这个键（这是回归底线的一部分）。**线上的 `tags` 必给**：它不只是挑人的过滤集，维护通道的适用领域也靠它表达，没有它的线会让「谁有权反应维护度量」出现第二种答案。
- **权重只算一遍。** 分数仍在整张非完成子图上算，过滤集删的是行，动不到分数 —— 于是「过滤集里挑第一名」和「全图里挑第一名」用的是同一份排序。

## 3. 过滤的判据

> 一个节点在这条 cycle 的选材范围里 ⇔ 它**一个 tag 都没有**，或者它的 tag 与 cycle 的过滤集**相交**。

- 一个节点可以挂几个 tag：`art,writing` 的节点同时归两条线管，哪条线先挑到它都算数。
- **没有 tag 的节点留在所有范围里。** 这是保守方向的选择：漏挡的代价是多跑一个节点，误挡的代价是一条线的活永远没人做 —— 后者的代价要一直挂到有人发现为止。所以「没打 tag」的意思始终是「不设限」。
- cycle 没设过滤集时（只有存量记录才有这种行），整张图都是它的范围。

## 4. 为什么过滤只落在「挑下一个节点」这一步

过滤是一个**挑选规则**，把它塞进别的地方都会长出自己的麻烦：

- **正在跑的那个节点不归它管。** cycle 认领一个节点时就把它记进了自己的持有关系，报的是认领记录里的那个节点。过滤集即使和它不匹配，它也照跑完、照常收尾 —— 半路改掉一个已经在跑的节点，等于把认领它时那个决定掀翻。
- **依赖关系一个字不改。** 挡住的跟依赖没满足是两回事：被挡住的节点既不变状态、也不标 `shelved`、依赖边原样，它是「这一轮不挑它」，离「它出事了」还隔着好几步。

## 5. 跨线就绪时的停顿

本线过滤集里还有就绪节点就照旧挑第一名；整张图都没有就绪节点就照旧报停；**本线没有、图里有就绪节点只是被 tag 挡住的 —— 停。**

停在这里是把选择权交回用户手上：一条线的活做完了，另一条线要不要开工、什么时候开工，由他说了算。机器能算的是「本线没活了、别的线有」，算不出来的是「现在开第二条线对不对」—— 那是一句人话，就该由人来说。

停的那一刻给出一句话的 `reason`，它是给人写的：点名哪些节点就绪、被哪些 tag 挡住，并给出另开一条 cycle 能直接抄的命令。停手照旧把这条线转成 `inactive`；那条别的线的活原样留在图上，没有东西被锁住，也没有一个节点被标死。

## 6. `--node` 点名的那个节点

用户亲手点名的节点按既有语义处理：就绪的照走，不就绪的拒绝并说明。过滤集管的是「没点名时挑谁」，管不到人手敲出来的 id —— 静默吃掉一个刚被敲出来的名字，等于把用户刚做的一个决定藏起来。两种走法都要把「它不在本线的范围里」说出来；只说「它现在开不了工」，人会往依赖没满足上想。

## 7. 空过滤集（回归底线）

写的那一侧一律要给 `--tags`，空过滤集这条分支因此只留给**存量记录**里不带 tag 的 cycle：

- 过滤集是空的 ⇒ 整张图都是它的范围，挑选结果、记下的路径、记录的形状与没有这个功能时逐字节相同。
- 节点没有 tag ⇒ 它在任何过滤集下都留在选材范围里，图里不多一个键。
