# conduct 的节点 tag 与 cycle 分流

> 这份是**节点 tag 与 cycle 分流**的设计出处：词表、过滤语义、判据，以及每个字段落在哪个文件。
> 状态与推进的其余部分见 [`./conduct-state.md`](./conduct-state.md)；派发与鉴权见
> [`./conduct-dsh-dispatch.md`](./conduct-dsh-dispatch.md)。
>
> 规则一句话：**节点可以没有 tag；cycle 的 `tags` 是这条线的选材范围（它一生里每一次挑选都用这
> 一份）；过滤只作用在「挑下一个节点」这一步。**

## 0. 为什么要有它

图一旦同时装着文案、代码、图像三类活，「这条线在做什么」就散在每一轮的挑选结果里 —— 人想开
一条只做文案的线、或者只想让一条线碰代码，没有办法说出来。

tag 就是这句话：给节点打 tag（这件事属于哪一类活），给 cycle 一个过滤集（这条线在哪些节点里
挑人）。`pf cycle start --tags coding` 开出来的线，从此只挑代码的活 —— 第一个节点到
最后一个节点，用的是同一份过滤集。

## 1. 词表

三个词，固定：

| tag | 含义 |
|---|---|
| `writing` | 文案 |
| `coding` | 代码（`engineering` 是它的同义词，账上只写 `coding`） |
| `art` | 图像 |

- 词表是**给人看的一份约定**，engine 不拿它当闸门：词表外的 tag 在 stderr 警告一行，照收。
  真冒出第四类工作时写进去就能用；警告只是让人知道自己站在词表外。
- 同义词在**记账的那一个入口**折成记录里的写法（`dag-manage` 与 `state-manage` 各自的 tag 解析入口），
  节点和过滤集两边都走它，于是同一类活只有一个词。过滤一律按字面比。
- 两个工具各有一份这三个词（一个管节点、一个管 cycle 的范围），靠一组用例
  钉住它们的写法一致。

## 2. 字段落在哪里

```
.pf/ideas.json         nodes[<uuid>].tags   ["coding", "art"]     可选；不打就不出现
.pf/state.json         cycles[<id>].tags    ["coding"]            必给；开 cycle 时写一次
```

- **节点上的 tag 落在 DAG 里**（`ideas.json`），因为它是图的一部分：谁属于哪一类活，和它
  依赖谁、什么状态一样，是图自己说的话（`dag-manage` 有它的写入口与读视图）。
- **cycle 上的过滤集落在 `state.json` 的 cycle 记录里**，因为它是**这条线**的属性：一条线只挑
  一类活，这件事跟着线走，不跟着某一次挑选走。开机那条命令把过滤集**同时**交给挑选与记录——
  挑选发生在 cycle 建起来之前，只写记录就太晚了，第一个节点就会挑到别的线的活；此后每一次挑选
  都从那里读回来复用，「第二次挑到了别的线的东西」这种漂移没有地方发生。
- **两边不对称**：节点上的 tag 可选——没有它时，`ideas.json` 里那个键根本不出现（这是回归底线的
  一部分）。**cycle 上的 `tags` 必给**：
  `cycle start` / `cycle create` 拒收没有 `--tags` 的调用。这条不只是挑人的过滤集——维护通道
  （见 `conduct-state.md` 的维护通道一节）的适用领域靠它表达，没有它的 cycle 会让「谁有权反应维护度量」
  出现第二种答案。存量 cycle 不追溯。
- **权重只算一遍**：`urgency` / `importance` 仍在整张非完成子图上算（`pf dag list` 的老规矩），
  过滤集删的是行，动不到分数。所以「过滤集里挑第一名」和「全图里挑第一名」用的是同一份排序。

## 3. 过滤语义

一条判据，管两侧：

> 一个节点在这条 cycle 的选材范围里 ⇔ 它**一个 tag 都没有**，或者它的 tag 与 cycle 的过滤集**相交**。

- 节点可以有多个 tag：`art,writing` 的节点同时归两条线管，哪条线先挑到它都算数。
- **没有 tag 的节点留在所有范围里。** 这一条是保守方向的选择：漏挡的代价是多跑一个节点，
  误挡的代价是一条线的活永远没人做 —— 后者的账要一直挂到有人发现为止。所以「没打 tag」
  的意思始终是「不设限」，跟「哪儿都不属于」差着一整条线的活。
- cycle 不给 `tags`（存量记录才有这种行）时，整张图都是它的范围（见「空过滤集」）。

## 4. 为什么过滤只落在「挑下一个节点」这一步

过滤是一个**挑选规则**，把它塞进别的地方都会长出自己的麻烦：

- **正在跑的那个节点不归它管。** cycle 认领一个节点时就把它记进了自己的 `holding`，
  `plan()` 报的是认领记录里的那个节点。过滤集即使和它不匹配，它也照跑完、照常收尾 —— 一条线的范围是
  给「挑谁」用的，半路改掉一个已经在跑的节点，等于把认领它时那个决定掀翻。
- **DAG 的依赖关系一个字不改。** `art` 节点照样能等 `writing` 节点做完才就绪，该等的还等：
  挡住跟依赖没满足是两回事。被挡住的节点既不变状态、也不标 `shelved`、依赖边原样 ——
  它是「这一轮不挑它」，离「它出事了」还隔着好几步。
- **排序仍然只有 `dag-manage` 一处实现。** 过滤在它拿到那份已经排好序的清单**之后**删行，
  管线侧一行优先级规则都没有。两处实现同一个判断，就是两处会分头漂移的地方。

## 5. 跨线就绪时的停顿

| 情形 | 行为 |
|---|---|
| 本 cycle 过滤集内还有就绪节点 | 照旧按 importance × urgency 挑第一名 |
| 过滤集内没有，图里有就绪节点只是被 tag 挡住的 | **停**，`reason` 点名：哪些节点就绪、被哪些 tag 挡住、建议另开一个 cycle 并给出 `cycle start --tags ...` 的整条命令 |
| 过滤集内没有，图里根本没有就绪节点 | 照旧：报「图里没有就绪节点」并停 |
| cycle 没设 tags | 整张图都是它的范围（见「空过滤集」） |

**为什么第二种情形要停下等人。** 这个停顿正好把选择权交回机主手上：一条线的活做完了，
另一条线要不要开工、什么时候开工，由他说了算。机器能算的是「本线没活了、别的线有」，
算不出来的是「现在开第二条线对不对」—— 那是一句人话，就该由人来说。

`reason` 会被原样念给用户听，所以它是给人写的：标题、id、tag 一行一个节点，最后一条能直接抄
的命令。两处会说这句话（手里没有节点时挑一个、收尾时挑下一个），同一处代码生成，说出来的话就
一模一样。

停在这里时这条线**转 `inactive`**（`cycle status <id> inactive`，一条命令，没有 paused /
completed 之分）：本线眼下没活了，要不要接着跑由人说了算 —— 图会长出新节点，人把它放回 `active`
它就接着挑。那条别的线的活原样留在图上（节点还是 `todo`），reason 里写着怎么开一条新 cycle 去接它
—— 没有东西被锁住，也没有一个节点被标死。

## 6. `--node` 点名的那个节点

`next --after <node> --node <id>` 是机主亲手点名。它按既有语义处理：**就绪的节点照走，
不就绪的节点拒绝并说明**。过滤集管的是「没点名时挑谁」，管不到人手敲出来的 id —— 静默吃掉一个
刚被敲出来的名字，等于把机主刚做的一个决定藏起来。

两种走法都要把「它不在本 cycle 的过滤集里」说出来：

- **放行**：动作的 `note` 里写清点名的节点、它的 tag、这条 cycle 的过滤集，再照点名把它钉住。
  （`apply()` 把 `open_node` 换成重规划出来的 `dispatch`，所以这句话挂在 follow 上一起走。）
- **拒绝**：`reason` 里两条理由并列 —— 「它现在不是就绪节点」和「它不在本 cycle 的范围里」。
  只说前一条，人会以为是依赖没满足。

## 7. 两条 active cycle 并排时的指令可见性

tag 分流之后，同一个项目里开两条 cycle 变成常规操作（一条 `coding`、一条 `writing`）。
指令账里的 `cycle` 作用域条目只对**它绑定的那条 cycle** 可见，两条并排时也一样：

- 位置能钉下来就按位置比：收尾那一步自己知道这条线是谁，一个摆在那儿的事实，不用猜。
- `instruction list` 的位置由指针给出；两条 active cycle 并排时指针分不出读者站在哪条线上，
  于是用**读者自报的节点**（`instruction list --node <id>`）反查：节点 id 在整个 DAG 里唯一，
  拿着它的那条 cycle 就是它所属的线。
- 两样都没有时，`cycle` 条目**两边都不念**，并在默认视图里补一句解套的话。沉默必须能被读成
  「说一句你在哪条线上」，而不是「这里没有约束」。
- `node` 作用域的条目一个字没改：位置钉得下来时按位置比（与只有一条 active cycle 时完全一样），
  钉不下来时退回它自己的寿命判据（绑定的那个节点还没 `completed`）。那是条目的寿命，
  跟读者站在哪儿无关。
- **写的那一侧也要有人点名**：`instruction add --scope cycle` 两条并排时用 `--cycle <id>` 说清记在哪条
  线上（`--node <id>` 同理），两样都绑不上就拒收 —— 没有绑定的条目会被读成人人可见、永不失效，
  那正是这一节要避开的结果。

## 8. 空过滤集（回归底线）

写侧一律 `cycle start` / `cycle create --tags`，空过滤集这条分支因此只留给两处：**存量记录**里
不带 tag 的 cycle，与过滤助手自己的空集路径。

- 过滤集是空的 ⇒ 整张图都是它的范围，挑选结果、记下的路径、`state.json` 的形状与没有这个功能时
  逐字节相同；连一次额外的 `dag-manage` 子进程都不会起（助手对空集提前返回）。
- 节点没有 `tags` ⇒ 它在任何过滤集下都留在选材范围里，`ideas.json` 里不多一个键。
