# tools/ 的模块形状：一份装载器，加列在它名下的公共件

`tools/` 不是包，也没有任何东西把它挂到 `sys.path` 上。一个文件要用另一个文件，走的是「按路径
加载」，而这条约定只有一处实现：`tools/shared/loader.py`。这是本文件要定的口径。

## 一棵工具树长什么样

三个工具同一条规则：`<工具>/` 顶上是**入口**（人能直接跑、`pf` 按相对路径转发的那些），它背后的
**机器**放在旁边 —— 一簇子目录（`conduct/state/`），或者就是这个工具的几份模块
（`dag/graph.py`、`issue/storage.py`）；`tests/` 放这一层的测试。入口与它背后的机器挨着
（`state-manage.py` ↔ `state/`、`conduct_pipeline.py` ↔ `pipeline/`、`ledger-merge.py` ↔
`ledger_merge/`），所以改名一处时另一半就在手边。

哪一份**必须**留在哪一处是硬约束，写在那个工具自己的 `AGENTS.md` 里（例如合并驱动必须留在
conduct 根，`pf` 的 `merge-ledger` 转发按那个相对路径找它）。

外加一簇**插件**目录（`conduct/features/`，每格一个功能）：那里装的是数据加代码，不归核心机器，
见下一节。

## 一个功能是一个文件夹

`conduct/features/<名字>/` 每格装一个功能：声明（`feature.json`，数据）与实现（`impl.py`，代码）。
装进来多少由这个目录里摆着什么决定 —— 删掉那个文件夹，功能跟着消失；放回去，它照旧在，核心的
机器文件一个都不必动。声明里写着每个度量点名的那个方法；那张技能卡就住在同一个文件夹的
`cards/<语言>/<方法名>/` 里，随它一起装、一起卸 —— 卡上写明它绑的是哪个功能，安装脚本把它链成
`~/.agents/skills/<方法名>`，文件夹一删，那条链就成了死链，下一次安装把它收走。

- **注册表住在 `pipeline/` 里，按路径取用。** `pipeline/feature_registry.py` 是核心认得功能的
  全部家当：四种旋钮、三个时机、两个动作，以及一份声明要满足的规矩。两个包都要读它 —— 管线那侧
  问它要动作（`feature_host.py`），状态那侧把功能认领的旋钮并进旋钮表（`state/knobs.py`）—— 而
  两个包按约定互不 import，于是走装载器：按路径加载、`register` + `reuse`，一个进程里只留一份，
  收尾、清单和体检问的是同一份。验证器就是它上面的 `verify()`，调用方只有测试套件和 `pf doctor`，
  管线的路由上不接；查什么、为什么这样分，见 `conduct-state.md` 的「功能（feature）与维护通道」一节。
- **它只认标准库，外加装载器。** 与 `shared/` 里那几份同一副骨架：不 import 任何一个包，被谁加载
  都不会绕回自己。
- **落点有一个环境变量覆盖**，缺省是出厂的兄弟目录（`<conduct>/features`）—— 与树里其它部件同一条
  toolpath 规则，演练副本、沙箱各指各的。
- **这些文件夹归装它们的人**（或一次演练的沙箱），不归核心：核心只负责合并与查重，坏掉的声明由
  体检列出来，运行时不拦下一个节点。

## 装载器管什么

- **它只依赖标准库**。它是进公共件的入口，不能依赖自己被要求加载的那个文件，否则谁来加载它？
- **模块名只用来记录，本身不充当身份**。它决定相对导入在哪个名下解析、`sys.modules` 里留不留
  这一份、以及回溯里那个文件叫什么。没有任何一处按名字去取一个模块 —— 一旦按名字取，第二个调用方
  拿到的就是第一个调用方的那一份，两边的路径绑定与补丁会悄悄串线。
- **「同一个文件在一个进程里有几份」由调用方声明**，装载器是这条判断的正本。三种要求各自是一个
  显式参数：要一份自己的拷贝（测试夹具每个项目一份状态包、每次派发一份 spawner）；要全进程共用
  一份（锁的重入记录必须是一份，否则调用方自己持有的那把锁会把内层调用挡在门外）；加载完留在
  `sys.modules` 里（包必须先注册，它的子模块才找得到它）。
- **包与单文件走同一条**：包带上自己的目录，装载器替它完成注册。
- **项目根由调用方定，模块不留一条「自己算」的路径**：每条 CLI 在自己的入口把根解析一次、显式交给
  模块（`configure`，或状态包那个 `bind_paths` 的口子），谁也不在用到路径的那一刻回头去看 cwd ——
  同一进程里的第二个项目（又一个沙箱、又一次演练）于是不会读到第一个的 `.pf/`。

## tools/shared/ 里有什么

只放跨工具的原语，没有入口：

- `loader.py` —— 上面这条约定本身，外加 `load_shared(<stem>)`：`shared/` 里某个文件按目录取用的那道入口（落点、一个进程里的一份、注册名都收在这一处）
- `toolpath.py` —— 树里某个部件在哪：部件自己的环境变量，缺省是出厂的兄弟路径
- `jsonio.py` —— 全树 JSON 的读与原子写，以及三种读失败各自给的那句话
- `ledgerlock.py` —— 项目那一把跨进程锁：一次读-改-写期间谁都不许插进来
- `gitcmd.py` —— 问 git 的唯一种写法：cwd、解码、非零退出不抛，三处调用方都走它
- `clock.py` —— 记录里的时刻：两种形状各一个常量和一个「现在」，以及哪个记录用哪一种
- `ledger.py` —— 记录目录的契约：它的名字、它底下那几个固定落点、worktree 回主树那条判定、
  `~/.pf/config.json` 那一层的落点，以及「这个目录没 init 过」的判据与那句话。它知道 `.pf` 这一个
  词，不知道里面任何一条记录的形状
- `session-note.py` —— 一个节点的会话交接单：形状、读法、写方

除 `ledger.py` 之外，这里每一份都不认 `.pf`：装载器只按路径加载，`jsonio` 只读写一条 JSON 记录，
`ledgerlock` 只对交给它的目录上锁，`gitcmd` 只在一个项目里跑 git，`clock` 只给时刻，`toolpath`
只找部件。`ledger.py` 认这个词，
但仍然只认标准库、不加载任何东西 —— 要先有装载器才轮得到它，它不能反过来要求装载器；它也不在导
入时算任何路径，所以那个名字没有第二份会冻住的副本。

要按路径取东西的文件都带同一段引导（先载入装载器本身）。**这段引导没有正本可共享**：要加载装载
器，本来就得先拼出它的路径，而拼那条路径只能从本文件自己的位置算起（`tools/` 不在 `sys.path`
上，按名字取正是这套约定要挡的）。所以每个这样的文件都自己带一段最短的样板：算出 `shared/`、按
路径执行一次 `loader.py`、把它留在模块自己的一个名字下。引导之外，公共件都在上面这几处正本里，
取它们一律走 `load_shared`。

外加 `tests/`：这一层自己的套件，判据见下一节。

## 为什么按路径取，而不是把 `tools/` 做成包

另一条路是把 `tools/` 做成一个可导入的包，在一处把它的父目录写进 `sys.path`，之后文件之间按名字
import，谁也不用自己拼路径。本树不走这条，判据只有一条：**同一个文件在一个进程里必须能有几份**。

测试夹具给每个一次性项目一份自己的状态包，每份带着自己的 `bind_paths` 绑定。按名字 import 之后，
第二个沙箱拿到的就是第一个的 `store`：路径绑定与补丁悄悄串在一起，而两个沙箱的用例照样全绿。几份
拷贝在这里正是要保住的功能（「模块名只用来记录，本身不充当身份」说的就是这件事），把它收成一份才
是要拦的那种静默错。于是：

- **每一次调用自己一份**的按路径取：一次性项目的状态包、每一次派发的管线实现包与 spawner —— 第二
  个项目、第二次派发都要有自己的绑定，谁也不许读到上一个的。
- **一个进程一份**的也按路径取，然后 `register` + `reuse`：公共件。调用方之间共享它们正是它们的
  意思 —— 锁的可重入记录是一个进程一份，多出第二份模块，调用方自己持有的那把锁就会把内层调用挡
  在门外。
- 公共件的唯一入口是 `load_shared`（落点、一个进程里的一份、注册名都收在一处），引导样板由每个调用
  文件自带。

`shared/tests/` 是这一层自己的套件：不许 import 其他工具的夹具，要用的临时项目与那份装载器拷贝都
自己造，所以改 `shared/` 只跑这一份就能自证。四条套件的跑法在 `README.md` 的 Development 一节
（命令只在那一处写）。
